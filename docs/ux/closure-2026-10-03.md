## 2. #412: reasoning shown as the answer

Cause: the provider router already ignores every provider reasoning field (`reasoning`, `reasoning_content`, `reasoning_details`; a reply that is
only reasoning is an `EmptyCompletionError`). The leak is the model writing its working INTO `content` (gpt-oss-120b: five stored outputs on
15 September, one live on 3 October: "We need to access office records: db.read but we cannot actually run. In this simulation we must
assume ...").

**The fix is heuristic, and defence in depth.** It is not structural: the provider returns working in the answer field and no architecture
here can make that impossible. `deliberationLeak` (`src/agents/quality.ts`) refuses a body only on strong evidence, and the refusal is
written into the retry's prompt, so the next attempt answers instead.

My first widening was too broad and I narrowed it before closing: it added the ordinary verbs access, fetch, open, check and the modal
"cannot" beside the generic nouns "the policy", "the instructions", "the schema", which would have refused "We need to check the policy with the
accountant". Now: (a) call syntax; (b) token bleed; (c) a plan about answering beside a tool NAMED by its registry identifier (`db.read`), where
the wide verb set is safe; (d) the original calling verbs beside "the tool", "tool call", "parameters:" only. "the policy", "the instructions",
"the schema", "the description" and "in this simulation" are no longer machinery.

Regression (`tests/agents/reasoning-leak.test.ts`, 28 tests): provider reasoning fields ignored; a normal answer preserved; reasoning-only is
no answer; five leak shapes refused; sixteen legitimate neighbours survive ("We cannot access Google until you reconnect it.", "You need to
fetch the document from the source.", "This simulation shows the projected result.", "We need to check the policy with the accountant ...");
the refusal reaches the retry as a body problem; a 40-sentence legitimate answer passes; empty and malformed bodies are not leaks. There is no
streaming path in the router. #412 stays open as defence in depth until the model stops writing working into content; the Identity-proof
