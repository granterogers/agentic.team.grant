1. **Migration numbers.** Production already held a different `1023_the_health_reading_asks_the_cheap_question_first` and a `1027_the_pulse_reads_each_table_once` (efficiency workstream, 7 October; not on `main`), and other branches use 1023-1035. Mine were renumbered 1040 and 1041 while still pending. `main`'s 0906-1022 had already been applied on 6 October.
2. **The live definitions.** `app.hq_dashboard_layout_set`, `app.hq_dashboard_layout_reset`, `public.hq_dashboard_layout_set` and `public.hq_upload_target` on production were compared with the pre-migration definitions the rollback files restore (rendered on a replica): identical (whitespace aside). 3. **The live gateway** (v897) has the same set of RPCs as `main` and none of the efficiency branch's gateway changes, so replacing it with `main` + this work dropped nothing.
4. **The live page was not `main`'s.** Its `app.js` equalled `claude/efficiency-deep-optimization`'s (about 110 lines different from `main`; `account.js` too). Deploying a main-based page would have rolled that back, so exactly those two files' diff was carried into this branch (`git apply --3way`, clean). The page deploy's file-set guard then refused until the 52 new names (the overhaul's menu, dock, backdrop, dictation, eight textures, stone.css) were allowed by exact list (`--allow-new=`); nothing else differed.
