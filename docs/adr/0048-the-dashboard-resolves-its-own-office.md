# ADR-0048 — The dashboard resolves its own office, and a clone resolves nothing

**Status:** accepted · **Date:** 24 September 2026 · **Closes:** IR-1

## Context

Six modules under `web/studio` each opened with the same two lines:

```js
const API =
  window.HQ_API || 'https://<a project ref>.supabase.co/functions/v1/hq-api'
```

`app.js`, `office.js`, `session.js`, `chat.js`, `call.js` and — for the avatar
bucket — `data.js`. `web/voice/index.html` carried a seventh, and the inline
block in `index.html` an eighth.

That is one person's office written into generic product code, eight times, and
every consequence of it is bad and none of them is loud:

- **Somebody who clones this repository and deploys it gets a dashboard
  pointing at an office that is not theirs.** Nothing leaks — the gateway
  verifies the session with Supabase and checks its own `office_members` list,
  so a stranger is refused — but they are refused with a **401 and no
  explanation**, which reads as "this product is broken" rather than "you have
  not told it where your office is".
- The address is in eight places, so the day a project reference changes,
  seven of them are right.
- There is no state meaning *not configured*, so the page cannot say the one
  true thing it knows. CLAUDE.md's rule applies to a backend exactly as it
  applies to a reader: **you may say you could not look; you may not say there
  is nothing there.**

## Decision

**Nothing served to a browser names a particular office. A DEPLOYMENT names its
own, at deploy time, in a file that is not in the repository.**

- `web/studio/backend.js` is the single resolver. It reads `window.HQ_API` and
  derives every sibling address from it — sign-in, chat, voice, the voice
  token, the Google OAuth start, and the avatar bucket — so there is one base
  and no second place to drift. When nothing has named an office it returns the
  **empty string**, never a guess.
- `web/studio/config.js` is generated by `npm run config:site` and is
  **gitignored**. `index.html` loads it as a classic script before the module,
  and a 404 is not an error: it means this copy has not been configured.
- Both deploy paths generate it first (`deploy:hq`, `deploy:preview`), and
  `npm run deploy:page` substitutes the same base into the standalone voice
  page. Grant's deployments are unchanged in behaviour and need no new
  environment variable, because `SUPABASE_PROJECT_REF` keeps the default
  F-009 says must stay.
- `npm run check:backend-ref` is the structural regression, in the gate. It
  looks for the SHAPE of a Supabase project host anywhere under `web/`, not for
  a list of known references — an enumeration of offices would go stale the day
  somebody pastes a different one. `--prove-it` puts the fallback back, watches
  the check go red, restores, and watches it go green.

## What this deliberately does NOT do

- **It does not weaken the authorization boundary.** Grant's correction is that
  authentication should become invisible, *not nonexistent*. Nothing here
  touches who may call the gateway: a Supabase Auth session, verified with
  Supabase, plus the office's own membership list. The gateway's ADDRESS is
  public — the browser calls it — so moving it out of the bundle exposes
  nothing and hides nothing.
- **It puts no secret in front-end JavaScript.** `config.js` contains one URL.
- **It does not touch `scripts/` or `src/`.** F-009 records the decision that
  the 252 defaults there must STAY: those are operational commands, and an
  operator who must set an environment variable before every command is an
  operator who stops using the commands. What is different about `web/` is that
  it is **served** — nobody types a command to get it; it arrives in a
  stranger's browser.

## Consequences

- A fresh clone that has not run `npm run config:site` renders the prototype
  and reports that it could not reach an office, rather than silently calling
  somebody else's.
- Anyone adding a new address to the front end adds it to `backend.js` as a
  derivation, or the gate refuses the commit.
- The basecamp slug override in `index.html` now derives its base from whatever
  `config.js` named, so the experiment's own gateway follows the deployment
  instead of pinning it. ADR-0043's arrangement is unchanged; only the base it
  is built on moved.
