## How to read the evidence column

| Environment | Meaning |
|---|---|
| **mock** | The real Hermes process and/or the real office MCP function code, against a scripted OpenAI-compatible model double and/or a fake PostgREST. Evidence about Hermes behaviour and the function's code paths. It is **not** evidence about SQL, RLS, or any model's quality. |
| **local** | Measured on this machine (memory, timing). |
| **live** | A real external provider was called, through the guard (`scripts/hermes-m0/model-guard.ts`): allowlist of zero-priced models only, routing fields stripped, hard call cap. |

Matrices are in `docs/hermes/m0-evidence/` (`v4a`, `v4b`, `lifecycle-*`, `v5`, `v8`). Reproduce with the commands in the last section.

## Disclosures

* **The office's own funded key was used for M0's live calls**, through the guard, for zero-priced models only (81 free requests today at the final reading, of a 1000 limit). Hermes itself only ever held a dummy key.
* **One unattributed spend delta.** The key's account usage moved by **+$0.000336816** between the start of M0 (2.781219799) and the end (2.781556615). It occurred during early runs; every generation attributed from the final harness is exactly zero, and the final account totals across the V5 and V8 runs did not move. The key is shared with the office's own duties, so the delta is not attributable and is **unexplained**, not shown to be harness-free. The method was changed to per-generation attribution because the account total cannot decide it, and the criterion was not rewritten to force a pass.
* V4a, V4b and the lifecycle checks are **mock**: they prove Hermes behaviour and the function's code paths. They say nothing about SQL, row security, or model quality.
* Hermes was installed into scratch storage. A `/tmp/hm` symlink and `/root/.local/bin/python3.14` (created by `uv`) exist outside the repository and are removed at the end of the run.

## Method and reproduction

Everything is in `scripts/hermes-m0/` (lint-clean, typechecked):

```
npx tsx scripts/hermes-m0/v4a-baseline.ts   <out> <deno>
npx tsx scripts/hermes-m0/v4b-hermes-mcp.ts <out> <deno> <hermes-host>
npx tsx scripts/hermes-m0/v1-lifecycle.ts   <out> <deno> <hermes-host> [--only s1,s2,...]
OPENROUTER_API_KEY=... npx tsx scripts/hermes-m0/v5-free-model.ts <out> <deno> <hermes-host> <usage-baseline.json>
OPENROUTER_API_KEY=... npx tsx scripts/hermes-m0/v8-attribution.ts <out> <deno> <hermes-host>
npx vitest run tests/engines
```

Every found-nothing check has a positive control (V1-4 for V1-1, V1-6 for V1-5, V4b-8c for V4b-8, V9-3 for V9-1, V10-2 for V10-1). The model guard's pricing test was sabotaged (2 of 6 red) and the MCP function was sabotaged twice in scratch copies (office binding: V4a-7 red; scope check: V4a-8 red), then restored or discarded. The harness is never run against production and never sets a production flag.
