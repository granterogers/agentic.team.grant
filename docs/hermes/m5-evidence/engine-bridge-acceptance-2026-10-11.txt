Findings recorded by this run (each also in docs/hermes/INTERFACE-CONTRACTS.md section 5.3):

  * Hermes repairs an unknown tool name to the nearest offered one (a request for create_task landed on list_tasks). Harmless here because only read tools are
    offered, but it means a hallucinated call can be served as a different read than the model named; the recorded call (engine_run_calls) says which.
  * The office's MCP function narrows tools/list for an engine client, so Hermes configured with write tools in its include list is still never offered them.
  * A provider 500 keeps a Hermes run alive for ever; the bridge's no-progress limit is what ends it, and it frees Hermes's single slot (R7, R8).
