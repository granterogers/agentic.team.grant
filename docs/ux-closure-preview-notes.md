# External documents are read, searched and previewed on demand, without Import - notes (HQ-DOC-025 .. 031)

Branch `claude/ux-closure-preview` (from `claude/team-hq-ux-overnight`). Migrations **0990 and 0991 are UNAPPLIED to production**; they were proved only on the local replica `cand_prev2` (clean base `pbase` + this branch's unapplied migrations 0897-0981 + 0990 + 0991). Nothing was deployed, nothing touched production, and **no live Google call was made**: every Drive response in every test is a fake. The ledger is not edited. This file says what is now true per row and exactly what still needs a live Google account.

Intent (Grant): an external document does not need to be imported to be useful. A connected external document can be read, searched, indexed and previewed on demand while its source is connected. **Import** is a different act: it makes a durable Team HQ copy that survives the source disappearing. Read/preview/index are never Import.

## What was built

1. **A preview contract** (`src/documents/preview.ts`, one file, no imports, symlinked into `supabase/functions/hq-api/` and uploaded beside the entrypoint by `scripts/deploy/hq.ts`, as `file-text.ts` and `oauth.ts` are). A request for a document id answers one of five states:
   - `ready` (kind `text` | `pdf` | `image` | `held`, plus a payload), `loading` (the page's state while the gateway works), `failed` (reason, `retryable`), `unsupported` (reason, with the honest alternatives `open_source` / `import`), `stale` (cached derived content shown WITH the reason it may be old, never silently).
   - A `PreviewProvider` interface (`describe`, `howToShow`, `fetchText`, `fetchBytes`). **Only Drive implements it.** I inspected `src/notebook`, `src/notion`, `src/browser`: each indexes its own material through its own sync/jobs and none has an on-demand reader a gateway call can use, so NotebookLM, Notion and saved web pages are NOT given invented readers. For them the contract answers `ready` with the text their own sync already indexed (labelled "indexed earlier, not read live"), or `unsupported` with the honest reason when nothing is indexed.
2. **On-demand Drive fetch, no binary kept.** The house pattern for reaching Google from a request is the gateway's existing `googleToken` (the operator's refresh token exchanged for a one-hour access token, as the Drive browser does); a job could not return bytes to a browser. Two new gateway sections (`supabase/functions/hq-api/index.ts`, placed beside the Drive browse, `office: true` semantics via the verified session office):
   - `document_preview?id=&project=` returns the contract above.
   - `document_preview_file?id=&project=` streams a PDF or image from Drive to the browser in the response. Size cap 25 MB (checked on metadata, on `content-length` and on the real length), content type from an allow-list (PDF, PNG, JPEG, GIF, WebP; **SVG is refused**), the leading bytes must match the label, `cache-control: private, no-store`, `x-content-type-options: nosniff`, `content-security-policy: default-src 'none'; sandbox`, `inline`. **No Storage call exists on this path** (a gateway-source test asserts none, and the unit and replica proofs run against a Drive fake that throws on any other host).
   - What Google formats become: Docs -> `text/plain` export, Sheets -> `text/csv` (first sheet only, said on the page), Slides -> `text/plain` (not the PDF export `drive.read_file` uses, which would have to be kept to be shown), plain/markdown/CSV/JSON -> downloaded text, Word (.docx) -> bytes read once and the text taken out in passing, PDF -> bytes streamed, text taken out in passing, images -> bytes streamed. Everything else (zip, video, Excel, PowerPoint, Forms, Drawings, SVG, folders) is `unsupported` with an honest sentence.
   - **Persisted: derived data only.** `migrations/0990`: `public.document_previews` (the source's modified time, checksum, size, kind, when text was last derived, whether `documents.content` holds preview-derived text; closed to every role, row security on) and two functions behind public wrappers (`hq_document_preview_plan`, `hq_document_preview_record`). The extracted text goes into the existing `documents.content` / fingerprint / `fetched_at`, so the existing `document_chunks` trigger indexes it and `search_documents` finds it; `preview_excerpt` (0960, generated) then follows. The source's own modified time is written to `remote_updated_at`.
   - **Stale rule.** `sourceChanged` compares the source's `modifiedTime` (and `md5Checksum` where Drive has one) with the cache, by instant not by string. Content is fetched again only when they differ. A re-open within 60 seconds of the last check asks Drive nothing and mints no token; after that one metadata call is made, and an unchanged source is not exported again. A changed source is read again and the page says so. If Drive cannot be asked, the cache is shown as `stale` with the reason (and Try again only when trying again could help). A file Drive no longer has (404 / in the bin) is NOT served from the cache as if it were not.
3. **Disconnected source (0896), decided: not previewable at all, not even from the cache.** The safer reading and the one consistent with `search_documents` / `best_chunks` / `project_knowledge`: the plan returns no text for a disconnected source, the gateway never contacts Drive for it, `document_preview_record` refuses to write for it, the stream is refused, and the page says the source is switched off (and hides Import, which would have to read it). An imported copy is Team HQ's own and is unaffected.
4. **Import stays separate and stays explicit** (`migrations/0991`). Text a preview derived is not the file: before this, an Import of a previewed PDF would have copied its text and no file. `app.document_material_held` now decides "does Team HQ hold what an Import copies": a stored file, or text a real read brought in - **not** preview-derived text. `hq_document_import` and `document_import_fulfil` were spliced from their live definitions to ask it (assertions confirm each landed). So Import of a previewed document still starts the 0960 fetch job (`drive.read_file`), the copy holds the file, and the drive read handler tells the database it has read the file (`app.document_preview_mark_read`, guarded so a database without 0990 is unharmed) before it completes the request. A document whose text a real read brought in (no preview) still imports instantly, exactly as 0960 left it (a control proves it).
5. **UI** (`web/studio/bc/docview.js`, `docthumbs.js` new, `shell.js`, `wire.js`, `miniatures.js`, `docsources.js`, `office.js` `readFile`, `docs.css`; classes prefixed `bcpv`, phone rules at the end of the block). The viewer asks for the preview on open and draws every state: a loading state (busy region), a failure with the reason and Try again (only when it can help), an unsupported state with Open source / Import to Team HQ, a stale notice above the content, a refetch notice, and one quiet line under the title: **"Read from Google Drive on demand · not copied to Team HQ"** versus **"Imported copy · kept in Team HQ, whatever happens to the original"** (and "Source switched off · nothing is read from it"). The Import press is unchanged and is the only path to a copy (the button inside an unsupported box just presses it). Imported and held documents never call the preview.
6. **Thumbnails: browser-side, chosen on purpose.** Rendering a PDF's first page on the server would be a rendering subsystem with a new dependency to make a picture this browser makes itself with the pdf.js it already ships. So when the viewer has the PDF's first page (or the image) in hand it makes a ~220px JPEG and keeps it in `localStorage` (`docthumbs.js`: keyed by document id + the source's modified instant, 60 entries, 90k characters each, every access guarded) and the wall tile shows it, with the cached text excerpt as the fallback for text documents. Consequences, stated plainly: it is per device and appears only after a document has been opened on that device; a source that changed shows no stale picture (proved with a control); nothing is sent anywhere. No Drive `thumbnailLink` is used.

## Not verified, and traps for whoever does it
- **`hq-api/index.ts` is not type-checked by `tsc`** (it is a Deno file outside `tsconfig` include). The new block is covered by source-reading tests and the pure module is fully typed; a deploy probe (`npm run deploy:hq`) is the first time the Deno bundle is compiled. `deploy:hq` must be run from a tree where `src/documents/preview.ts` exists (the script uploads it as `preview.ts`).
- Deployment order: apply 0990 and 0991 (`npm run migrate`; 0991 splices 0900 / 0960 functions, so it follows both), then deploy hq-api and the worker, then the web page. The worker's call to `app.document_preview_mark_read` is guarded, so a worker deployed before 0990 is harmless.
- Playwright stubs the gateway. The real gateway has never served `document_preview*`; CORS for the binary section reuses the JSON section's headers and has not been probed from the real origin (CLAUDE.md's own trap about server-side fetch hiding CORS defects applies - probe with the page's origin).
- `hq_document_import` still does not itself refuse a disconnected source; only the page hides the press. Whether the server should refuse is a policy call left to Grant.
