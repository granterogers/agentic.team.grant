## Deliberately deferred, with reasons

### Event subscriptions

Not configured, because a request URL must be **publicly reachable and respond
to Slack's verification challenge**. Nothing is deployed yet, so configuring it
now would fail verification and leave the app in a broken state.

Added later via `apps.manifest.update` once the app has a URL — no manual
clicking, and no need to recreate the app.

### Config-token rotation

**Not performed.** The rotation mechanism is specified
(`docs/design/slack-app-lifecycle.md`) but cannot run yet: rotation returns a
new token pair that must be persisted durably, and there is currently **no
durable store**. Verified tonight:

- Supabase REST responds (200), but PostgREST cannot execute DDL
- No `exec_sql`-style RPC exists on the project
- No database password and no Supabase management token are available

So a rotated pair would exist only in an ephemeral container. Since the refresh
token is **single-use**, a lost rotation means the config token must be
regenerated by hand anyway — the exact outcome rotation was meant to avoid.

> **Rotating without a durable store strictly increases risk.** Correct order is:
> credentials table first, rotation second. The config token expiring is a
> ~30-second regeneration, not a disaster — so letting it lapse is the cheaper
> failure.

**To unblock:** either a Supabase database password / connection string, or a
Supabase personal access token for the Management API. Then the table and
rotation land together, as Phase 2 specifies.

## Bot scopes requested (17)

`chat:write`, `chat:write.customize`, `channels:read`, `channels:manage`,
`channels:history`, `groups:read`, `groups:history`, `im:read`, `im:write`,
`im:history`, `mpim:read`, `mpim:history`, `reactions:read`,
`reactions:write`, `users:read`, `team:read`, `files:write`

`chat:write.customize` is the load-bearing one: it carries per-staff identity
presentation (name and icon per message) from a single app, which is the V1
identity architecture. Note the known limit — an overridden identity is
**cosmetic**: not `@mentionable`, not DM-able, and absent from the member list.
True staff identity lives in Postgres, never in Slack message authorship.

No `connections:write` — Socket Mode is not used, so no `xapp-` token exists.

## ⚠️ Standing constraint: never enable public distribution

Slack's 2025 rate-limit restrictions **exempt internal custom apps** —
`conversations.history` and `conversations.replies` stay at 50+ requests/minute
with a 1,000-object limit. The punitive 1-request/minute, 15-object tier applies
to **commercially distributed non-Marketplace** apps.

Enabling distribution on this app would silently reclassify it and cut
history-reading throughput by roughly 50×, **with no error explaining why**.

This belongs on every manifest review and is an explicit negative assertion in
Gate 4.
