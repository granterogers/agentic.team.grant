## 1. A duty had been queued for eight hours — REAL, FIXED

`verify:drains`, 5/8:

```
FAIL no real job has been waiting longer than 15 minutes
     — 1 waiting, oldest 494m (office.propose)
```

`office.propose` is the proposal round wired for #49/#272 the previous evening:
migration 0473 created the duty, and the handler `proposeHandler` went into
`src/office/pass.ts` in the same commit. **The deployed worker was built before
that commit**, so the job was enqueued on schedule at 22:15 and never dequeued
— `attempt` 0, eight hours, no error anywhere, because nothing had failed.

This is the trap CLAUDE.md names in one line: **a migration is not a deploy.**
It is recorded there against 0283, where `duty:notion-sync` put back three
containers the migration had just deleted. Same shape, seven months of file
history apart.

`npm run deploy:worker` → v519, and the job completed inside the same drain:

```
d65635ea complete: committed without review (deterministic path)
```

`verify:drains` is **8/8** after the deploy. The other two failures in that
suite were the same job seen through two more checks — the injected-control
teardown and the dashboard-agreement check both counted it — so all three had
one cause.

**What the suite got right:** it is in the gate precisely because a dead worker
once left Grant waiting fifteen hours while the heartbeat logged 1,440
successes. It caught this one in eight.

## 2. `verify:judge` reported a working judge as broken — FALSE FAILURE, FIXED

```
compare failed — cohere/north-mini-code:free returned no content
  (finish_reason=length, 19375 tokens spent)
cohere/north-mini-code:free   3/5 correct · 0 wrong · 1 position-flipped · 1 unreadable
the pinned judge CANNOT discriminate: 3/5. Any better/worse verdict from
npm run replay is currently worth nothing.
```

The same model, the same corpus, twenty minutes later: **5/5**. It is a
reasoning model, and on one pair it spent its entire 16,000-token budget
thinking and returned nothing. CLAUDE.md records the small version of this — a
judge given 2,000 tokens spends them thinking and returns no content — and the
budget here was already raised once, so a bigger budget is not the answer.

Three things were wrong and all three are fixed:

- **The survey, which is the ONLY way to choose a judge on evidence rather than
  on preference, had never run.** `npm run verify:judge -- --survey` died on
  `operator does not exist: text = integer`: `usable_models.pricing_prompt` is
  TEXT, because OpenRouter sends a decimal string and the column keeps it
  verbatim. Nobody had reached for the survey until the day the pinned judge
  went red. One `information_schema` query settles a column's type.
- **A pair that did not answer is asked once more.** A truncation is a one-off;
  a model that genuinely cannot answer will not answer twice either.
- **The score is taken over the pairs that came BACK.** An unreadable reply is
  the instrument abstaining, which the file's own header already says about
  position flips. A judge that abstains on most of them still fails — with
  those words, not with "cannot discriminate", because the remedy is different.

Run with the survey, now that it works:

| model | score |
|---|---|
| `cohere/north-mini-code:free` (pinned) | **5/5** |
| `dots-studio/dots-3-note-preview:free` | 5/5 |
| `inclusionai/ling-3.0-flash-sante:free` | 5/5 |
| `inclusionai/ling-3.0-flash-fin:free` | 4/5, one position flip |
| `minimax/minimax-m2.7:free` | 0/5 — five unreadable |
| `minimax/minimax-m3:free` | 0/5 — five unreadable |
| `openrouter/free` | 0/5 — five unreadable |

So the pinned judge is correct, and there are two proven alternatives if it
degrades. **`npm run replay`'s better/worse verdict is worth something again.**

The gate's decision is extracted to `src/eval/usable.ts` and unit-tested in
`tests/eval/judge-usable.test.ts`, because a rule that costs twenty model calls
to exercise is a rule nobody breaks on purpose. Deliberately removing the
abstain guard turns the fourth test red; it was watched.

## 3. `verify:routing-breadth` 10/11 in the gate, 11/11 on a re-run — VARIANCE, KEPT OPEN

Thirteen cases did not reach their specialist during the gate; the same suite,
unchanged, passed on the next run. The free-tier models are not deterministic
and `temperature: 0` does not make them so — CLAUDE.md records two consecutive
runs of an unchanged corpus giving 16/19 and 16/18.

**The re-run is not a fix and is not recorded as one.** The named misses are
worth keeping because a pattern across runs is the signal, not any one run:

| said | wanted | got |
|---|---|---|
| "Talk me out of doing this. What am I missing?" | quality | Claire |
| "I want to understand the money side of the relaunch." | finance | growth |
| "Everything grinds to a halt once they sign." | operations | quality |
| "I need you to find the hold-up in how we deliver this." | operations | research |
| "Should we enter the enterprise market or stay with SMB?" | strategy | growth + research |
| "Which channel should we stop spending on?" | growth | finance |
| "which aquisition chanel is working best" | growth | operations |
| "so I need to let people know about the price thing" | communications | finance |
| "I want to know more about this before I decide." | research | strategy |

Twelve of the thirteen were decided by the LITERAL matcher, not the semantic
layer — the trigram lookup found *a* subject and won, so the model was never
consulted. That is the shape CLAUDE.md already describes for whole-message
matching, and it is the thing to look at next rather than the threshold.

## Verdict

The deployed stack answered for everything the gate asks of it once the worker
carried the handler its database already had a duty for. **One live defect, one
false alarm inside the instruments, one variance finding worth watching.**

The instruments came out of this worse than the product did: the judge's survey
mode had never run, and the judge gate's arithmetic turned an abstention into
an accusation. Both are the found-nothing shape in a new costume — a check that
has only ever been read is not a check.
