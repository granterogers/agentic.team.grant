## Defects found and FIXED

**1. The schema could not hold a file Grant uploaded.** `documents.connector`
was NOT NULL. All 55 rows arrived through Notion, NotebookLM or MCP, so the
constraint had never been tested — and it made `origin = 'yours'` unreachable.
Migration 0177: nullable, with a stronger invariant replacing it.

**2. My own constraint then broke every existing writer.** `origin` defaults to
'yours' and every ingestion path sets `connector` without knowing `origin`
exists, so the first insert after 0177 failed. Migration 0178 derives `origin`
from the connector when the caller has not said. **A constraint that requires
every existing caller to change in the same commit is a constraint that will
break something you did not think of.**

**3. "Call the team" was dead.** The most prominent control in the interface —
the one Grant asked to be prominent — wrote to `.talkstate`, an element removed
from the rail at some point since. It renders, it passes every layout check, and
it photographs perfectly. Only pressing it finds this.

**4. The ribbon's "1 blocked" was dead**, in the most confusing way available: it
navigated to the project you were already on and re-rendered an identical page.

**5. `--ink-3` was 2.75:1 against the ground** — under WCAG AA's 4.5:1, and
systemic, because that token colours every label, every meta line and the
brandline. Now 4.59:1.

**6. The 12px type floor was breached in four places** — labels at 11.5px,
document badges at 8.5px, the stage pill at 11px — and fourteen touch targets
were under 44px at phone width.

## Defects FILED, not fixed

**#43 — a project with documents cannot be deleted at all.**
`documents.project_id` carries no ON DELETE action while tasks, collections and
relations all cascade, so the same delete half-works depending on which tables a
project has rows in. Not fixed here because whether deleting a project should
destroy 55 real documents is a decision about Grant's data, not a tidy-up. The
same shape applies to `job_state_transitions`, which prevents deleting a job.

**#42 — staff slugs disagree.** The database identifies staff by role
(`chief-of-staff`); the studio prototype uses first names (`claire`). Both
resolve to the same eight people today. It will fail *quietly* once the frontend
reads real data, because `crewBy()` falls back to `CREW[0]`.

**#44 — project name resolution is largely not working.** `verify:identity` is
17/28. Eleven failures around resolving a project from its own name, creating
aliases, and asking before creating a near-duplicate. Purging leftover fixtures
moved it by one, so this is real rather than pollution.

## Failures investigated and found NOT to be defects

**`verify:agents` — 3 failures, all stale test expectations.** Reproduced each
in isolation:

- *"the same job commits once the output is reviewed"* — the test sets
  `state = 'committed'` on a `queued` job. The only allowed path into
  `committed` is from `committing`, and the state machine correctly refuses the
  shortcut. The gate works; the test skips the machine.
- *two project-switching checks* — `app.resolve_project` returns the right
  project when the target is active, verified directly. The failures depend on
  the fixture project's status, and switching into an archived project is
  correctly refused by `app.enforce_switch_target_active`.

**`verify:slack` was reported as failing and is not.** It needs more than 150
seconds; given 420 it is 62/62. A suite killed by a timeout looks identical to a
suite that failed.

**Three CORS "failures" were the checker's opinion.** It asserted that every
endpoint should allow the `authorization` header from production and localhost.
`voice-token` allows neither — and the page calls it as
`fetch(MINT, { method: 'POST' })` with no headers at all, while `PAGE_ORIGINS`
holds only production by design. **Widening an allowlist to satisfy a test is
the test making the system worse.**

**52 layout "failures" were a touch rule applied to a mouse.** A 26px collapse
chevron under a cursor is standard; inflating every desktop control to 44px to
satisfy a phone guideline makes the desktop worse.

## The audit's own faults, which took longer to find than the product's

Worth recording, because a test that lies in either direction is worse than no
test.

- Comparing `innerHTML.length` reported half the interface as dead — a toggle
  that swaps one class changes no characters.
- A 390px Playwright viewport without `hasTouch` reports `pointer: fine`, so
  every rule written on `pointer: coarse` was inert and fourteen controls were
  reported as too small **after** they were fixed.
- Chromium returns `oklch()` verbatim from `getComputedStyle`, so an rgb-only
  contrast parser read every agent monogram as 1.00:1.
- An element painted with a gradient has a transparent background-color, so the
  backdrop walk sailed past it and called the filled Call button illegible.
- Node block-buffers stdout to a pipe, so a killed run showed **nothing** and a
  working script looked hung.
- A test that only cleans up afterwards passes or fails according to how the
  last run ended.
