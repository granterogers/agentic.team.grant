## What changed overnight

**The office-token experience is gone.** That was the correction, and it went
in first. A clean browser is asked for an email address and nothing else; the
link signs it in; it stays signed in. The office's own key is now a machine
credential only — the browser never holds it and never sees it.

Then, in order: the to-dos stopped moving when ticked, Stuck became a column
like the others, the two settings scopes separated, every module got a heading
and a colour, documents gained four ways to order and one arrangement that
follows Grant between devices, outputs became readable, and the four links that
handed him back to the old interface are gone.

Three migrations of Grant's own data were touched and all three are additive:
`office_members` (one row, his address), `document_orders` and a `surface`
column on `dashboard_layouts`. Nothing was deleted except the abandoned pairing
table, which had never held a row anybody wanted.

## Authentication

**What now exists.** Supabase Auth — this project's own identity system, which
had never been used (`auth.users` held zero rows) — issues a person a session.
`hq-api` verifies that session **with Supabase** and checks
`public.office_members`. Machines still present `hq.api_token`, unchanged,
compared in constant time. **ADR-0043** records the whole trace and the
reasoning.

**Is the token UX completely gone?** Yes. There is no field, no paste, no code,
no Telegram approval and no pairing anywhere in the interface. The word does
not appear on the sign-in surface. The legacy key is still *read* from storage
if an old browser has one, so none of Grant's existing devices were signed out
by this change — but nothing offers to put one there.

**What a clean browser experiences.** An email field and one button. Verified
across four states: clean, signed in, refreshed, and a new context carrying
storage (a restart). 17/17.

**Security.** Not weakened. A stranger who signs up at the identity layer gets
a perfectly valid session and the office refuses it, because *Supabase says who
proved an address and `office_members` says who the office works for*. Nothing
decodes the JWT locally — a token a function merely decoded is a token anybody
can write. A forged session is refused; asserted every run.

## One thing to know about the deployment

The experiment runs **its own copy of the gateway and the voice endpoint**
(`hq-api-basecamp`, `voice-basecamp`), because this branch's gateway source is
ahead of `main` and behind the backend branch, and deploying it over the shared
one would have dropped somebody else's work. The default Team HQ and the shared
functions are untouched by anything done tonight. Removing the copies is a named
step in ADR-0043.
